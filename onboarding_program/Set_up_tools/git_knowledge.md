# Have you used Git before? If so, in what context?

- I have used Git multiple times before since I started my course in 2023. I use Git mainly for version control, code pushing/pulling and code sharing. For example, I want to get anyone to work on the same project, so create a repo and push it onto Github is essential. Git is needed for later synchronization, since everyone has different progreeses, fetching Git is needed before you start working on the project to avoid conflict. To avoid conflicts efficiently, we can create branches to work on our own, then review each member's branch before merging all the branches and push the code.

## Which Git client (if any) did you choose? Why? (e.g., GitHub Desktop, Git in VS Code)

- I have used both of the Git clients, which are Github Desktop and Git and VS Code. Personally, i used Github Desktop more often because the interface is user-friendly so I can perform Git commands without the need to type in them manually. For Git in VS Code, if I am currently working on the project, maybe I can type in Git commands to check the status or update the repo since it is much more convenient than opening another app. Using whichever client is up to your choices, either between simplicity and convenience.

### What was the most interesting thing you learned about Git today?

- I learned many intriguing things, such as discovering more about many other Git commands apart from common ones like git push, git pull, git status, and git fetch (I mostly use these commands), the concept of staging and committing, the importance of branching (I don't usually create branches unless I contribute to other people's repo), and how to write meaningful commit messages (in the past I only wrote like "changes" or "updates" for messages since I don't find writing long messages necessary).
